# Orion connected UI implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Replace prototype simulations with the approved responsive React interface connected to real Orion services.

**Architecture:** Consume the completed engine plan's typed same-origin API. Shared workspace/query state invalidates on decisions, settings and job transitions. The prototype remains the visual authority, extended with operation/job/connections surfaces using the same design system.

**Tech Stack:** React/TypeScript/Vite, CSS tokens, local Feather/font assets, Vitest/React Testing Library, installed browser QA.

**Spec:** `docs/superpowers/specs/2026-10-08-orion-modernisation-design.md`.
**Dependency:** `2026-10-08-orion-engine.md` tasks 1–6; its record/API signatures are binding.

## Global constraints

- Bundle fonts/icons locally for the installed app; respect reduced motion and keyboard navigation.
- All newly migrated screens use native light/dark design tokens; no unreadable legacy dark-panel islands.
- All routes and primary actions remain accessible at narrow widths.
- Any confidence score must come from defined evidence or the provider; do not reuse the prototype's illustrative percentages.
- Return configured/not-configured states, never saved secret values.
- Use generated temporary media fixtures; real personal-media mutation is outside automated verification.
- Keep PR #3 draft until every plan and required validation is complete.

## Review focus

1. Failed approved items must remain recoverable: task 2.
2. Global search after category filtering must search all media: task 2.
3. Reload during a job must restore persisted progress: task 3.
4. Stale plans must disable execution pending revalidation: task 3.
5. Settings changes must invalidate overview/sidebar immediately: task 4.

Create `frontend/package.json`/lockfile, Vite/TypeScript configs, `src/api/client.ts`, `types.ts`, `state/WorkspaceProvider.tsx`, `App.tsx`, `styles/tokens.css`, `layout.css`, shared `components/`, focused `pages/` and test fixtures. Keep sample posters in demo fixtures; real items display returned art or a genuine file-kind icon. Bundle fonts/icons with licences. Keep the accepted prototype available as reference.
