ORION / LOCAL WORKSPACE

Installation guide

Orion runs on your computer and serves its interface in your browser. This guide covers the modern source build. No published installer is linked here. Check the repository for current release availability; draft release artifacts are for maintainer review.

Requirements

Use Python 3.11 or 3.12, Node.js 24 and Git. Node is needed to compile the UI. The compiled app uses the Python runtime and does not need a running Vite server. A Windows bundle is unsigned unless its release notes explicitly say otherwise. Native macOS and Linux packaging has not been verified.

Build and launch

git clone https://github.com/Varun-SV/Orion.git
cd Orion
python -m venv .venv

# Activate on Windows PowerShell:
.\.venv\Scripts\Activate.ps1
# Activate on macOS / Linux instead:
# source .venv/bin/activate

python -m pip install -r requirements-web.txt
npm --prefix frontend ci
npm --prefix frontend run build
python -m orion run --frontend-dir frontend/dist

The launcher opens a URL bound to 127.0.0.1. Complete first-run setup, select your source and destination folders, and review items before approving a plan. Keep the launcher terminal open while work runs. Closing the browser alone does not stop the backend.

Stop or choose another port

python -m orion stop
python -m orion run --port 8766 --frontend-dir frontend/dist

If the default port is occupied, choose another port. Orion recognises an existing instance for the same data directory. To isolate a test library, pass --data-dir ./orion-test-data to both run and stop. Do not start testing against your live library.

Credentials and optional services

Metadata and Jellyfin/Emby connections are optional. Add credentials in the installed app. The OS keychain stores them; where secure storage is unavailable, explicitly choose session-only credentials. Music fingerprint identification also needs a separately installed fingerprint tool when configured. Provider or server connectivity is not verified by this public site.

Upgrade

Stop Orion before updating source or replacing a bundle. Back up your media and app data, then rebuild the UI and install the runtime dependencies for the selected version. The database migrator backs up existing databases before schema upgrades and refuses schemas newer than the running version. See the recovery guide before downgrading or restoring.
