ORION / LOCAL WORKSPACE

Backup & recovery guide

The job journal helps explain and recover recorded work. It does not replace an independent backup of your media.

Before an upgrade

Stop the local backend using python -m orion stop, supplying the same --data-dir if you chose one. Preserve the app data directory and a separate backup of your media. The default data location is %APPDATA%\Orion on Windows, or ~/Orion when APPDATA is absent. An explicit --data-dir overrides the default.

The app data directory holds organizer.db and prefs.json. If SQLite -wal or -shm files remain, preserve the whole directory together. Do not copy only the live database while jobs are writing. Keychain credentials are separate from this directory.

Database migration failures

Existing databases receive a consistent SQLite snapshot before schema upgrade. These files are named organizer.db.backup-<timestamp>-<id>. Failed migrations stop startup. Preserve both the database and snapshot; use a compatible app version when restoring an older database.

Stop all instances before restoring. Preserve the current app data directory as a separate copy, restore a known consistent backup as a complete data set, and restart with the matching app version. Do not combine an old database with unrelated current WAL files. A newer schema cannot be opened by an older Orion build.

Interrupted organisation

After restarting, formerly running jobs are marked interrupted. Open the Job centre and inspect the job and recorded operations before retrying. Reconnect unavailable source or destination volumes first. Check partial copies and reported path conflicts rather than moving files by hand while Orion is running.

Completed operations are recorded separately from pending or failed operations. Retry is offered only for eligible jobs. Destination files are not overwritten. Cross-volume transfer records and verification guard deletion of originals; cancellation can leave reviewable partial work.

Preview undo

Undo is a new job linked to a recorded batch. Review its proposed paths before approval. Orion checks recorded file state and refuses unsafe reversals when files have changed externally or an original path is occupied. Only unchanged sidecars created by that batch are eligible for removal. Undo cannot reverse arbitrary later edits or replace lost media.

Privacy and reports

The installed UI and API share a loopback origin. Optional providers and media servers receive the data needed for identification and library lookups. Keys are stored in the OS keychain or explicit session-only mode, and exports exclude credentials. Reports contain original and final paths: review them before sharing.

The public demo uses fictional fixture data only. It cannot reach your installed backend, read your media or execute a real organisation plan. The public site stores its colour theme in browser local storage.
